## Encargo (intake)

Pase de diseño UX para la **UI admin de investigación de auditoría** de ERPify (PWA, Backoffice).
Entregable de diseño (documento UX), **no** código. Su salida desbloquea la implementación de 4.2b.

Pantallas en alcance:

   (actor `actor_type`/`actor_id`, rango de fechas, recurso `resource_type`+`resource_id`, `level`,
   `action`). Paginación keyset (cursor) ya existente.
2. **Reconstrucción de jornada** (UX-DR3) — seguir el hilo de un actor por `actor_id` +

3. **Detalle de entrada** (UX-DR4) — `action`, actor, `correlation_id`, recurso, `ip`, `user_agent`,
   `occurred_on`, `metadata` (JSON).
4. **Presentación PII-aware** (UX-DR5) — actor pseudonimizado/anonimizado se muestra COMO TAL;
   nunca payload sensible ni PII de negocio.

## Decisiones tomadas

### D-base (ronda 0 — bifurcaciones de interacción)

- **D0.1 Detalle = Drawer lateral.** `<RecordSheet>` read-mode sobre el timeline; cerrar
  devuelve al scroll. (Deep-link por URL queda como mejora posible, no obligatoria — se revisita
  en la ronda de detalle.)
- **D0.2 Jornada = Ambos.** Pivote (un click desde una entrada: «seguir a este actor» / «ver esta
  correlación») para ENTRAR + un modo «Jornada» agrupado por correlación para LEER.
- **D0.3 Timeline base = `<DataTable>` denso + divisores por día.** Reutiliza el contrato de listas;
  máxima densidad/escaneo; keyset prev/next; mono para ids.
- **D0.4 Modo de trabajo = Coaching** (decisión por decisión antes de redactar).

### Rondas de coaching

#### Ronda A — superficie base del timeline

- **A1 Columnas = Completo (7):** `hora · nivel · acción · actor · recurso · correlación · ⋯`.
  Orden por defecto `occurred_on` desc. `correlationId` como chip compacto en la fila (clave para
  agrupar jornada de un vistazo).
- **A2 Acción = Humanizada + token crudo secundario.** Consecuencia de diseño: mapa curado
  `Record<action, label>` para acciones conocidas (`BANK_ACCOUNTS_VIEWED` → «Cuentas bancarias
  consultadas», `ACCESS_DENIED` → «Acceso denegado», `GDPR_ERASURE_EXECUTED` → «Borrado GDPR
  ejecutado», …) **+ humanizador determinista de respaldo** para acciones no mapeadas / `ROUTE_*`
  abiertas (quita prefijo `ROUTE_`, title-case). El **token crudo se renderiza siempre** como línea
  secundaria mono (fidelidad forense). Coste asumido: mantener el mapa; el respaldo evita drift duro.
  Sigue el patrón `Record<Enum,T>` de `docs/rules/frontend.md`.
- **A3 Nivel = Badge dot-first + acento lateral izquierdo en filas `security`** (token
  `--color-security`). El badge rotula → color nunca es el único canal.
- **A4 Actor = Chip por `ActorType`** (icono+tipo · id truncado mono copiable): `user · id` /
  `system` (sin id) / `api_key · id` / `anonymous` (sin id). El anonimizado GDPR se trata en la
  ronda PII (ver OQ-1).
- **A5 (derivada) Orden/sort = solo `occurred_on`** (desc por defecto, conmutable a asc). No se
  ofrece sort por otras columnas: el keyset cabalga el eje `(occurred_on, id)` y ordenar por otra
  columna lo rompería. Decisión técnica, no se pregunta.

#### Ronda B — filtros, paginación, mecánica de jornada

- **B1 Barra de filtros = segmentado de nivel (Todo/Activity/Security) + rango de fechas
  (`<DateField>` desde/hasta) siempre visibles; panel «Filtros» (con badge) para actor (tipo+id),
  recurso (tipo+id) y acción.** Cubre los ejes de investigación más frecuentes sin abrir nada.
- **B2 Paginación = prev/next por páginas** (patrón `BanksPagination`: par siempre renderizado,
  `disabled` cuando el link del sobre es null, nunca oculto — gobernado por el ADR de keyset).
- **B3 Modo Jornada = toggle explícito `[Timeline]/[Jornada]`.** «Jornada» (agrupación por
  `correlation_id`) requiere un actor fijado; si no hay actor seleccionado el toggle va `disabled`
  con pista («fija un actor para reconstruir su jornada»). Se entra por pivote (ronda C) y se lee en
  este modo agrupado.
- **B4 Ventana por defecto = ninguna.** Al abrir, primera página newest-first (`occurred_on` desc);
  filtros de fecha vacíos; el usuario acota cuando quiere. Sin datos ocultos por sorpresa.

#### Ronda C — drawer de detalle, metadata, PII

- **C1 Drawer = secciones Qué / Quién / Sobre qué / Correlación / Metadata** (definition-list
  agrupada por significado forense). Cabecera: acción (humanizada + token crudo) + badge de nivel +
  pivotes. `occurred_on` completo + relativo en «Qué».
- **C2 Metadata = JSON crudo formateado, read-only, copiable** (`<CopyButton>`). Cada clave/valor
  como **texto escapado** (jamás `dangerouslySetInnerHTML`/`innerHTML`). Guard de tamaño/profundidad:
  si el objeto excede un umbral, trunca con affordance «copiar crudo» (no revienta el drawer).
- **C3 Actor anonimizado = chip distinto** («👤⃠ anonimizado (GDPR)»), sin id legible (el UUID nuevo
  no se muestra como id normal), `ip`/`user_agent` = chip `[REDACTED]`. Se lee a la primera que NO es
  identificable. En el **detalle** el *tell* es `ip`/`user_agent === [REDACTED]`; en la **fila**
  depende del flag de OQ-1 (degradación elegante si no existe).
- **C4 Pivotes = tres** (actor / correlación / recurso). Todos **re-filtran el propio log de
  auditoría** (seguro). El recurso se muestra como **id copiable, sin deep-link** a su página de
  negocio (frágil: recurso borrado, `resource_type` no mapeado, cross-context). + «Copiar id de
  entrada» y «Copiar correlación».

#### Ronda D — estados, acceso, tiempo, responsive

- **D1 Acceso = funcional ahora + permission-denied diseñado pero dormido.** La pantalla consume
  4.1 y es accesible desde el backoffice; `<AccessDeniedScreen>`/`<EmptyState permission-denied>` se
  especifica y se activa con RBAC. El **gating real de la ruta pública/PII es prerrequisito de
  backend antes de prod** (follow-up trackeado, no de esta UI).
- **D2 Tiempo = hora local con offset visible + ISO completo en el detalle.** Vía `dateTimeProvider`.
  Fila: hora local `HH:MM:SS.mmm` bajo divisores por día. Drawer: fecha+hora local con offset, el
  relativo, y el ISO completo (con microsegundos + offset) copiable. Sin toggle UTC (YAGNI; revisita
  si aparece investigación cross-timezone).
- **D3 Responsive = móvil card-rows reducidas + filtros en sheet; Jornada/metadata desktop-first.**
  `<md`: card-row apilada (hora · nivel · acción · actor), tap → drawer, sin scroll horizontal. El
  trabajo pesado (Jornada agrupada, metadata grande) se optimiza para ≥ md.

#### Sistémico (no preguntado — heredado/derivado)

- Estados vía `<AsyncBoundary>` (idle/loading/empty/error); `<EmptyState>` first-run /
  filtered-to-zero / permission-denied; errores vía `<ProblemDisplay>` (RFC 9457 verbatim) + chip de
  correlación.
- **Read-only ⇒ sin selección ni bulk.** La fila solo activa el drawer; teclado ↑↓ + Enter, sin
  Space-select. `⋯` para pivotes/copia.
- Densidad compacta por defecto + `<DensityToggle>` (clave compartida `LIST_DENSITY_STORAGE_KEY`).
- En modo Jornada, los grupos por correlación mantienen estructura semántica (`rowgroup` + cabecera).
- **Estado de filtros en URL params, NUNCA en localStorage** (un `actor_id` es PII). Solo se
  persiste en localStorage lo no-PII: densidad y el toggle Timeline/Jornada.
- `ip`/`user_agent`/`metadata`/`action` = *tainted* → siempre texto escapado (React), nunca
  `dangerouslySetInnerHTML`/`innerHTML`. Copia vía `<CopyButton>` (nunca confía el valor como HTML).

## Decisiones cerradas (antes preguntas abiertas)

- **OQ-1 — RESUELTA = Opción A (materializar el flag).** Persistir **`actor_erased boolean NOT NULL
  DEFAULT false`** en `audit_log`; exponerlo como `actorErased` en fila y detalle. Tratarlo como un
  **hecho materializado** (no como optimización accidental): se conoce en la escritura, la escritura
  ya existe (el `UPDATE` del erasure), la lectura es mucho más frecuente y la consistencia queda
  concentrada en un punto. **Se fija en el mismo `UPDATE`** que el remint de `actor_id` + la redacción
  de `ip`/`user_agent` (no en el self-audit → hereda su atomicidad; el ADR D4 reconoce que el
  self-audit no es transaccional con el UPDATE). Justificación DDD: **tercer eje ortogonal** a
  `actor_type` (quién) y `level` (qué clase) — descarta plegar en `actor_type` (opción G: perdería
  «era user vs api_key» y conflagra ejes). Descartadas: **B** (centinela `[REDACTED]` → inversión de
  dependencia: la UI dependería de un detalle interno del erasure), **D** (derivar de
  `GDPR_ERASURE_EXECUTED` → acoplamiento accidental + múltiples falsos negativos + JOIN en la consulta
  caliente), **C** (incumple UX-DR5 e induce a malinterpretar la evidencia). `GDPR_ERASURE_EXECUTED`
  se conserva como **evidencia forense independiente** (pseudónimo en `metadata.anonymized_actor_id`,
  **parte del contrato del evento**, no clave incidental; actor = `system`), habilitando un
  *cross-check* de integridad (todo `actorErased=true` ⟺ existe ese evento con ese pseudónimo).
  **Test de invariantes** post-erasure: `actorErased ∧ actor_id≠original ∧ ip=[REDACTED] ∧
  user_agent=[REDACTED]`. Naming `actorErased` (no `anonymized`) para no colisionar con el `actor_type
  = anonymous`. *Trigger de revisita* (YAGNI hoy): tipar los eventos de cumplimiento cuando aparezca
  el 2º (`GDPR_EXPORT_COMPLETED`, `GDPR_ERASURE_FAILED`), en vez de claves libres en `metadata`.
- **OQ-2 — DECIDIDA: texto libre ahora** (autocompletado *derivado de datos* como fast-follow; nunca
  catálogo congelado — el ADR pide que la taxonomía emerja de las consultas).
- **OQ-3 — DECIDIDA: deep-link `?entry=<id>` desde el principio** (`encodeURIComponent` + carga 4.2a
  directa).
- **OQ-4 — DECIDIDA: diccionario curado + humanizador de respaldo** (token crudo siempre visible).
- **OQ-5 — DECIDIDA: hora local + offset, ISO completo en detalle, sin toggle UTC** (YAGNI).
