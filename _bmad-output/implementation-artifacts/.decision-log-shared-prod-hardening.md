## 2026-05-31 — code reconciliation: deploy.sh (approved by Sergio)

Sergio pointed at the pre-existing `scripts/deploy/deploy.sh`. Investigation found it
was **broken and prod-unaware** independent of this feature: it called `make cache.warmup`
and `make messenger.stop-workers` (real targets are `sf.cache.warmup` /
`sf.messenger.stop-workers` in symfony.mk — "No rule to make target"), ran every `make`
with no `ENV`, so against the prod stack it would use the dev overlay (no `--env-file`,
no prod secrets), and its README documented `DEPLOY_ENV`/`HEALTH_URL` the script never read.

Reconciled (commit `fix(shared): reconcile deploy.sh with prod env model`):
- `DEPLOY_ENV` (default `prod`) passed as `ENV=$DEPLOY_ENV` to db.migrate / sf.cache.warmup
  / sf.messenger.stop-workers / db.status — script now honors the README's documented var.
- Fixed the two broken make target names.
- `HEALTH_URL` derives from `SERVER_NAME` (default localhost), so prod health hits the served host.
- Added a `prod.env.check` fail-fast preflight for prod/staging (skipped on `--dry-run`),
  mirroring deploy-local.sh.
- README: documented DEPLOY_ENV/SERVER_NAME defaults + preflight; dropped the
  `HEALTH_CHECK=true` over-promise the script never implemented.

Verified: `bash -n` clean; `DEPLOY_ENV=dev ./deploy.sh --dry-run --simple` renders the
corrected commands; both `sf.*` targets now resolve via `make -n`.

Spec updated: deploy.sh added to Code Map, a checked task bullet, and a new acceptance
criterion. The distinction is now explicit — `deploy-local.sh` = cold stand-up on
erpify.local (`make deploy.local`); `deploy.sh` = day-2 ops orchestrator.

**Already matches reality (confirmed).** compose.prod.yaml implements required-secret
`${VAR:?}` for APP_SECRET / DATABASE_URL parts / Mercure / Postgres identity; runtime
hardening (`no-new-privileges`, `cap_drop`+minimal `cap_add`, `read_only`+`tmpfs`,
parametrized resource limits); `tls internal` via `CADDY_SERVER_EXTRA_DIRECTIVES`;
`backend` network `internal: true`. `make/config.mk` wires `--env-file $(PROD_ENV_FILE)`
for prod/staging. `.env.prod.example`, `prod.env.check`, `deploy.local`,
`PRODUCTION_SECURITY_CHECKLIST.md`, `docs/erpify-local-test-deployment.md` all exist.
