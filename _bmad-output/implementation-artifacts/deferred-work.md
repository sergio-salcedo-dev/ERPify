## Deferred from: code review of 1-1-declare-the-domain-exception-taxonomy (2026-05-07)

- `BANNED_PREFIXES` backslash escaping is inconsistent (`'Psr\Http\\'` and `'Symfony\Component\Messenger\\'` mix mid-string single backslashes with trailing doubled). Functionally correct in PHP single-quoted strings, but tried doubling all backslashes for clarity and PHP-CS-Fixer auto-reverted the change. Sustainable fix needs a tooling-config update (related to the broader "lint ping-pong" cleanup the Dev Agent Record already flagged).
- Architecture test regex misses several `use` patterns (`api/tests/Unit/Shared/Domain/Exception/TaxonomyArchitectureTest.php`): multi-line `use` statements with FQCN on the continuation line, inline fully-qualified references like `new \Symfony\Foo()`, grouped `use Foo\{A, App\B}` with mixed prefixes, and BOM-prefixed first lines. AC5 explicitly allows the simple regex approach and AR6 forbids adding `nikic/php-parser`, so this is a coverage gap to harden later (e.g., via `token_get_all`).
- No project-wide architecture rule (Deptrac, PHPat) enforcing hexagonal boundaries. The current guard is scoped to `Shared/Domain/Exception/` only. A repo-wide tool would extend the no-Symfony/Doctrine/HTTP rule across all domain folders.
- Missing fixture tests for the marker-precedence edge cases: subclass implementing zero markers, subclass implementing all seven markers, subclass overriding `type()` to diverge from the constructor `$type` (FR13 path). AC6 only pins the precedence fixture used by Story 1.3; the factory-level coverage belongs in Story 1.3.
- No test exercises `?Throwable $previous` chaining through to `getPrevious()`. Low-cost coverage add — not required by any AC.
- `context()` shape: closures, resources, non-stringable objects, and circular references are not rejected; mutable objects in the context array can be mutated by the caller after the throw. Dev Notes explicitly delegate redaction and shape enforcement to downstream layers (Story 1.2 ProblemDetails, Story 3.2 redaction denylist); anti-pattern #5 forbids constructor validation in this story.
- Update `_bmad-output/planning-artifacts/epics.md` AC6 wording per the Dev Agent Record's debug-log recommendation: replace "begins with `NotFound::class, Conflict::class`" with "preserves the implements-clause order among the marker FQCNs". Planning artifact lives outside this story's editable scope.

## Deferred from: code review of 1-2-introduce-the-problemdetails-value-object (2026-05-07)

- Reserved-key collision in `ProblemDetails::toArray()`: when an extension key equals `type` / `title` / `status` / `instance` / `correlation-id`, the `+` operator silently drops it. When `$detail = null` and an extension carries `'detail' => '...'`, the key slips into the body at the WRONG position (after `correlation-id`, not at slot 4). Spec sanctioned the `+` approach for non-throwing, deterministic merging. Push the contract to `ProblemDetailsFactory` (Story 1.3): factory must never propagate a reserved key from `DomainException::context()` into `extensions`. Pin with a factory test.
- Banned-imports test in `ProblemDetailsTest::testSourceFileContainsNoBannedImports` inherits the same regex gaps as Story 1.1's `TaxonomyArchitectureTest` (multi-line `use`, inline FQCN, grouped `use Foo\{A, B}`, BOM-prefixed first lines). A repo-wide hardening (Deptrac / PHPat) would close both at once.
- Architecture-import guard scope is single-file. When Story 1.3 lands `ProblemDetailsFactory.php`, that story's tests need the equivalent guard — or we extract a `glob()`-driven scanner once a third file shows up in `Shared/Application/Problem/`.
- JSON Schema fixture's `format: uri-reference` is advisory under `justinrainbow/json-schema` defaults. URI-shape enforcement for `type` values is owned by Story 1.3's factory contract; if the schema test should also enforce it, enable `Constraint::CHECK_MODE_VALIDATE_SCHEMA` and the format-checker chain.
- Numeric-string extension keys behave surprisingly with array `+` and `json_decode(associative: true)` (PHP coerces to int). Spec's `array<string, mixed>` rules them out by contract; the factory should reject them at construction or coerce. Not actionable in the VO.

## Deferred from: code review of 1-5-bridge-symfony-framework-exceptions (2026-05-07)

- `ProblemDetailsFactory::firstMatchingMarker()` phpdoc declares `class_implements()` returns `array<string, class-string>` but the precise PHPStan stub is `array<class-string, class-string>|false` (the `false` is for string-class-name args; for object args it's always an array). Pre-existing from Story 1.3 — not introduced by 1.5; cosmetic phpdoc tightening for a future story.
- `HttpException` constructor accepts arbitrary integer status codes; values `<100` or `>=600` cause `Response::__construct` to throw `\InvalidArgumentException`, which escapes the `ExceptionResponder` listener. Story 3.4 (FR39, last-resort static body) is the right place to wrap the listener body in a top-level try/catch.
- `HttpException::getHeaders()` (e.g. `WWW-Authenticate` on `UnauthorizedHttpException`, `Retry-After` on `TooManyRequestsHttpException`, `Allow` on `MethodNotAllowedHttpException`) is silently dropped by the bridge. RFC 6750 mandates `WWW-Authenticate` on 401s — losing it breaks OAuth/Bearer flows. Spec AC #5 anti-pattern explicitly defers header propagation to a future Story 4.x concern; this finding pins that defer.
- `Symfony\Component\Security\Core\Exception\LazyResponseException` (extends `\Exception` and implements `Security\Core\…\ExceptionInterface` but NOT `AuthenticationException`) would route to `unhandled-exception/500` once SecurityBundle is enabled. Today the package isn't wired (no firewall config); this surfaces when a future story adds it. Add an `instanceof LazyResponseException` branch (returning the embedded Response unmodified) at that point.
- `firstMatchingMarker()` ordering follows `class_implements()` which returns parent-declared interfaces before child-declared ones. Story 1.1's `testMarkerOrderingFollowsImplementsClause` only covers flat anonymous classes (all markers in the same `implements` clause). A subclass that ADDS a marker on top of an inherited one would resolve to the parent's marker, contradicting the "first-declared marker" intent of FR12. Not introduced by Story 1.5; Story 1.1 follow-up to either harden the precedence model or document the multi-level limitation.
- Behat's `HttpRequestContext` keeps mutable `$headers` instance state with no `@BeforeScenario` reset. The `Background:` block re-sets `Accept` for each scenario, but other headers (e.g. `Authorization`, `Content-Type`) from prior scenarios in the same suite linger. Adding `features/shared` to the default suite (Story 1.5) increases the cross-scenario surface. Pre-existing context design; future hardening adds a `@BeforeScenario` `clearHeaders()` hook.
- Multi-byte / RTL-override / control-character `getMessage()` strings flow verbatim into `ProblemDetails::title` for the Symfony-bridge branches (and Story 1.3's existing branches). `JSON_UNESCAPED_UNICODE` keeps them literal. Epic 3 (`title` redaction) owns the sanitisation; this finding pins the gap.
- Hardcoded `http://localhost` URLs in `api/features/shared/error_contract/symfony_bridges.feature` are a workaround for `FoB SymfonyExtension` reusing context service instances across suites (so a per-suite `baseUrl: ''` override doesn't take effect). Functional but ugly — a structural fix would refactor `HttpRequestContext` to accept per-test baseUrl overrides or use a fresh suite-local instance. Documented inline in the feature; flagged here for a Story 4.1-or-later cleanup.
- No PHPUnit listener-integration test was added for the new branches — Story 1.5 deliberately chose Behat per CLAUDE.md's "Behat preferred" guidance, and Story 1.4's `ExceptionResponderFunctionalTest` (WebTestCase) still pins the listener wiring. Code reviewer flagged the absence as a coverage gap; the gap is intentional but worth noting if the project later re-prefers PHPUnit functional tests.
